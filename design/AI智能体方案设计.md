## 1. 编制说明

本文件说明智能体「如何工作」，而不是罗列调参结果。读者对象为评委与行业专家：先看清分层与数据流，再看知识如何进入决策、合同如何约束输出。

系统面向路桥隧日常巡检与台账填报。输入是现场或航拍图像目录，输出是可入库的七字段巡检记录。感知、检索、填报三件事分开：模型看图，工具提供规范与历史病例，合同层按桥梁 / 轨道两套业务规则落库。推理链路全部走开源底座与本机服务，不依赖外网闭源接口。

文中每一项能力、每一个数字都对应包内代码与实测产物；未实现的设计（如学生模型蒸馏、奖励后训练）在 §9 明确标注为「未执行」，不作为已完成成果陈述。

## 2. 行业问题与建设目标

### 2.1 业务问题

城市桥梁与轨道外观巡检长期面临三类矛盾：

1. **图像多、口径碎。** 同一工点既有桥面航拍，也有墩身、支座、梁底近景；轨道侧常见混凝土、钢筋、支座钢件混在同一画面。仅靠通用视觉分类，容易把锈色、渗水、裂缝写成同一类。
2. **规范在书里、经验在旧档里。** 巡检员判病要对照养护规范用语，也要参考历史同类照片。二者若直接「抄近邻标签」，会把邻桥、邻帧的病害写到本图上。
3. **台账字段有分工。** 桥梁记录需要名称、缺损类型、性状描述和评定标度；轨道记录在既有作业习惯里只落缺损类型，名称、部位、描述、标度留空。智能体必须按业务合同填报，不能把两套表头混成一张「什么都写」的通表。

### 2.2 建设目标

建设一套可离线部署的**巡检填报智能体**：看图、查规范、对照历史病例，在合同约束下写出标准化记录；一次任务覆盖目录内全部影像，条数与输入守恒；并能在「判得更全」与「判得更快」之间做出可解释的取舍。

## 3. 设计原则

| 原则 | 含义 |
| --- | --- |
| 感知与填报解耦 | 视觉模型只给出本图观察；工具命中不得直接写入正式标签 |
| 证据可追溯 | 规范条文与训练图文近邻进入提示的证据槽，供研判参考，不改写合同字段 |
| 合同先于生成 | 桥梁 / 轨道字段合法性由规则层闭合，不靠模型「自觉」 |
| 开源可复现 | 主模型、检索模型、智能体运行时均为开源组件，权重与代码可随环境恢复 |
| 现场可运行 | 按单卡推理、断网、小共享内存的巡检机房约束设计，不预设开发机超额资源 |
| 判定成本入架构 | 现场按 `run.py` 首尾计时并在队间做对数归一，「多调一次大模型」是成本项，必须在设计期权衡而非事后补救 |
| 改动过留桥门控 | 任何改判策略先在按桥留出的 dev 调参、lockbox 只看一次；负结果如实归档，不进入默认路径 |

## 4. 总体架构

智能体按分层组织：上层只调度，下层只举证，最外层只验收。同一套代码提供**两种运行模式**，由 `--config` 显式选择，**提交与现场跑分均使用默认轻量模式**；两种模式都已实测复现（见 `REPRODUCIBILITY.md`）。

> 提交口径：现场只跑模式 A。模式 B（27B 专家）作为已完成的研究分支保留在代码与文档中，
> 可一键切换验证，但**不在提交依赖路径上**——提交包不需携带 51G 教师权重，也不会出现“代码跑不出结果”的风险。

| 模式 | 判定路径 | 330 条实测时长 | 线上得分 | 适用 |
| --- | --- | --- | --- | --- |
| 快速（默认，提交与现场用） | 冻结 2B 图文嵌入 + 自训监督头 | **41.3–43.7s** | 72.18 | 线下现场跑分（时长占线下 28%） |
| 精度（研究分支，不随提交） | 上述 + 27B 自训 LoRA 教师只复判轨道病害行 | **172.5–197.1s** | 72.67 | 已完成实验与线上归档；本次不提交 |

主数据流（默认快速模式）：

1. `run.py` 从第一行开始计时，扫描「桥梁 / 轨道」目录（只读目录名与文件名，不展示、不打印影像内容）。
2. 按场景分桶：轨道、桥近景（文件名含「第N跨」）、桥航拍（其余）。
3. Qwen3-VL-Embedding-2B 对需判定的图逐张产出 2048 维向量，与病例库使用同一模型和同一预处理，保证可比。
4. 监督头给出判定：轨道直接定类型；桥近景先定完好 / 病害，判病害时由相似度加权 kNN 在病例库上投出类型与评定标度。
5. 桥航拍走**代价感知门控**（§5.4），预注册阈值下不翻转为病害；每条航拍行的概率写入审计。
6. 描述取自按病害类型 / 视角预置的代表句（BGE medoid，已剥离标注过程标记）；轨道侧描述与标度按台账口径置空。
7. 合同层校验七字段结构与闭集合法性，条数与覆盖率相符后发布 `result/result.json` 与 `infer_time.json`。

精度模式在第 4 步之后追加一次受控专家调用：仅把已判病害的**轨道行**交给 27B 教师重判组合标签，桥梁行与完好行一律不动。该模式已完成实验并留档，但**本次提交与现场跑分不使用**（代价是线上少 0.49 分，换来单一自洽路径与不依赖易失的 51G 教师权重）。

## 5. 智能体能力分层

### 5.1 感知层：冻结的开源图文嵌入模型

感知由 **Qwen3-VL-Embedding-2B** 承担（官方开源权重，`base_model: Qwen/Qwen3-VL-2B-Instruct`，apache-2.0；2.1B 参数，bfloat16）。它以「每图一向量」的方式工作：整图按最长边 1024 缩放后送入，取归一化后的 2048 维向量。

三条明确约束：

- **不做蒸馏、不做微调。** 该权重原生使用，仓库内无 adapter、无 LoRA 字段；训练只发生在其向量之上的判定头。历史上带「蒸馏」字样的模型是 27B 变体的命名，与本 2B 无关。
- **整图送入，不按左右幅裁剪。** 「左幅 / 右幅」是资产台账槽位，不是裁图指令。
- **表示与病例库同源。** 训练集 3402 条影像的向量由同一模型离线产出并缓存，判定时的向量空间与建库时严格一致。

### 5.2 判定层：判别式头为主，生成式专家为可选精修

| 组件 | 结构 | 训练数据 | 参数量 | 说明 |
| --- | --- | --- | --- | --- |
| 轨道类型头 | 22 类多项 LogisticRegression（C=4） | 轨道标注 800 条 | 45,078 | 直接输出闭集原串；组合标签作为独立类收录 |
| 桥近景完好/病害头 | 二分类 LogisticRegression（C=4, balanced） | 桥标注 2602 条 | 2,049 | 阈值 0.8 |
| 桥类型 / 标度 | 相似度加权 kNN(k=10) 投票 | 520 条近景病害案例向量 | —（案例库存储） | 类型冲突时按得票权重取胜 |
| 病害描述 | 按类型 / 视角的 BGE medoid 代表句 | 训练集金标描述 | —（文本表） | 只作措辞参考，不抄邻图标签 |
| 轨道组合标签精修（精度模式） | Qwen3.8-27B + 自训 LoRA | 2642 条闭集已修正 SFT 数据，83 步，train_loss 0.162 | LoRA r=32/α=64，12 个 target（含 GDN 的 `in_proj_*`） | 只改轨道病害行类型；非法输出保留头结果 |

为什么默认路径不用 27B 主判：这不是「小模型更强」的信念，而是分层实测结论。在按桥留出的 dev / lockbox 上，桥侧病害类型精确匹配头为 0.531 / 0.591，27B 教师只有 0.315 / 0.321——教师判桥会砸分；而轨道组合标签 set-F1 教师 0.670 / 0.653 明显优于头 0.642 / 0.606——头判轨道会漏组合。于是让两者各管自己擅长的部分：头定「有没有病 + 主类型」，27B 只把轨道单标签升级成组合标签。线上 72.18 → 72.67（+0.49）即这一分工的净效果。

### 5.3 认知与调度层：合同编排，而不是自由对话

正式字段只由合同链写出。链路为：

`输入包 → 任务合同 → 场景路由 → 图像向量 → 判定（头 / 专家）→ 候选规范化 → 本体映射 → 校验 → 序列化 → 落盘`

已退役、不再改写模型判定的模块包括：健康门强制「完好」、金标整句封口、开放专家路由改标、自由 ReAct 多轮改标。保留的是**非改判**的合同动作：空置不该填的字段、轨道标签闭集约束、一轮不确定复询。这样智能体像巡检员填表：可以再看一眼，不能私自改规范。

### 5.4 合同与治理层：两套台账一套引擎

| 字段 | 桥梁台账 | 轨道台账 |
| --- | --- | --- |
| `questionCategory` | 由目录名「桥梁 / 轨道」写入，不经模型猜测 | 同左 |
| `bridgeName` | 必填；测试工点为新桥，名称不可从历史桥名库映射，填报时使用工点占位名称 | 必须空（非桥梁对象） |
| `defectLocation` | 既有台账该栏为空，保持空置 | 必须空 |
| `filename` | 照片编号，主键 | 同左 |
| `defectType` | 闭集或「完好」 | 闭集或「完好」，允许多标签顿号连接 |
| `defectDescription` | 据本图性状直写 | 必须空 |
| `ratingScale(1-5)` | 完好为空；确认病害时落 2–4 档合法标度 | 必须空 |

校验失败不得用「完好」顶替。不确定回路最多复询 1 轮。发布前检查输出条数等于输入影像数，否则不覆盖正式 `result.json`。

**航拍代价感知门控（不是硬编码规则）。** 航拍行并非一律写「完好」：判定层同样给出病害概率，只有 `p_disease >= threshold` 才翻成病害，类型与标度走同一病例库 kNN。阈值由翻转的代价平衡点推出——一条误翻会同时改坏 `defectType / ratingScale / defectDescription` 三个字段，两个留出集实测每条代价 −59~−62 分，而每条正确命中只赚 +26~+36 分，故需要精确率 ≥ 0.63~0.70 才净赚；当前 2B 头在航拍上任何阈值的精确率上限只有 0.33，因此预注册阈值取 0.95，结果是「不触发」。该门控默认关闭，开启需额外嵌入 203 张航拍图（41s → 约 80s），且现场不得依据测试集输出临时调阈值。每条航拍行的概率与门控结论都写入 `heads_only.json` 审计。

**病害→完好红线。** 任何后处理都不允许把模型已判病害的行改回「完好」；这类改写曾在实测中放大误差，已从治理层移除。

### 5.5 交付层

`run.py` 第一行即 `begin_time = time.time()`，结尾以 `time.time() - begin_time` 写入 `infer_time.json`（同时兼容 `inter_time` 键名），即**首尾全程墙钟**，与服务启动、权重加载是否发生在一起无关；`timing_manifest.json` 记录纯推理与进程总墙钟两值及 config / 模型 / 代码指纹，使任何时长声明都能回溯到产生它的那份产物。禁止用文件 mtime 或估算值填计时字段。

快速模式不启动任何推理服务；精度模式由 `run.py` 自行拉起并关闭 SGLang，若端口上服务的是别的模型会直接报错退出，不静默替换。

## 7. 领域知识工程

### 7.1 闭集本体

桥梁、轨道分别维护允许标签表（官方原始用语，含合法组合串）。序列化阶段轨道标签必须落在白名单；桥梁「完好」与各类渗水、锈迹、处治痕迹等按本体收录。模型输出若越出闭集，由校验器打回，不在治理层「翻译」成相近词。

### 7.2 规范 Wiki

规范侧将养护条文切成卡片，建立 BM25 与关系索引。检索问的是「这类画面规范怎么称呼」，不是「近邻那张图写了什么类型」。

### 7.3 历史病例库

金标索引覆盖训练集约 3402 条记录，含文本向量与图像向量。图文检索解决「像不像曾经处置过的病害」，证据摘要进入提示。**近邻类型不是本图答案**——这是巡检质检的基本纪律，也是本系统与「检索即分类」方案的分界。

部署要点：

- 快速模式仅需 4.0G 嵌入权重 + 21M 代码与头权重，单卡 / 无服务即可跑完 330 条，实测 41–44s。

## 9. 关键创新

**（1）合同式行业智能体。**
把「看图」和「填表」分成两个权威：模型对画面负责，合同对台账负责。工具与记忆只进入证据槽。这避免了通用 Agent 用规划器改写业务字段的通病。

**（2）双知识源、单裁决权。**
规范 Wiki 管「该怎么称呼」，历史图文库管「像不像旧病例」，本图视觉模型管「这张图是什么」。三路信息汇合后仍由合同链裁决，从结构上切断「检索命中即答案」。

**（3）成本感知的判别—生成级联。**
不预设「大模型更好」，而是按字段分派：冻结 2B 表示 + 4.7 万参数监督头负责高吞吐的有无判定与主类型，27B 自训 LoRA 专家只负责它实测更强的轨道组合标签精修。收益（线上 +0.49）与成本（时长 4.7 倍）都被量化并公开，两种模式都可用 `--config` 一键切换。

**（4）航拍代价感知门控。**
「航拍怎么判」不写成规则常量，而是把翻转的期望收益显式化：误翻一条同时改坏三个字段（实测代价 −59~−62 分/条），命中一条只赚 +26~+36 分/条，由此算出净赚所需的精确率 0.63~0.70，再与头在该桶上的精确率上限 0.33 比较，得出当前应当保守不翻转的结论，并把概率与门控依据写进审计文件。规则因此是可复核、可下调的工程决策，而不是「航拍一律完好」的魔法设定。

**（5）分专业二次研判与批次工作记忆。**
轨道近景里锈蚀、露筋、破损、混凝土裂缝在色彩上接近，主链之后可做材料族专项复检；连续航拍或同桥多视角时，已确认帧作为情境提示降低前后矛盾，同时明确禁止抄邻帧整句描述。二者均不改写合同字段。

**（6）按桥留出的门控纪律与负结果归档。**
所有改判策略都要过同一道门：训练 / dev / lockbox 按桥隔离，dev 调参、lockbox 只允许一次确认，线上只取最后一次提交。由此否决了若干「看着合理」的路径——27B 端到端主判（桥类型 0.321 < 头 0.591）、航拍启用病害头（净分 −0.5~−1.2）、逐图 VLM 生成描述（0.669 < medoid 0.680）、恒填标度「2」（低于现有头命中率）等。这些负结果连同测量脚本一并留在仓库里，构成可审计的取舍依据。

**（7）开源闭环与国产算力适配。**
感知、检索、调度、专家模型均在开源栈与国产加速卡上闭合，单卡 96G、断网机房可复现；教师与学生蒸馏 / 奖励后训练曾纳入设计，因阶段 A 教师未通过门控而**未执行**，本方案不将其列为已完成成果。

## 10. 可靠性与工程约束

- **数量守恒：** 非法记录进入 drop 台账，不得静默删条后报完成；发布前条数必须等于输入影像数。
- **失败语义：** 模型空响应、截断或越出闭集时保留监督头结果并计数告警，不得回落成「完好」，也不得丢行。
- **计时诚实：** `infer_time` 取 `run.py` 首尾全程墙钟；预热与权重加载是否计入取决于是否在入口之内，包内一律如实记录，禁止 mtime 或估算值。
- **确定性：** 精度模式关闭前缀缓存与重叠调度后两次端到端运行逐字节一致；与历史归档提交存在 1 行差异（轨道单 / 组合标签决策边界），差异与成因在 `REPRODUCIBILITY.md` 公开。
- **并发：** 单卡视觉服务 `max-running-requests=12`，与编排并行度对齐；快速模式无服务依赖，天然免除显存抖动风险。
- **推理隔离与安全合规：** 思维过程不进入正式 JSON、证据态和普通日志；测试与生产影像仅供模型静默读取，禁止预览、截屏或导出像素用于人工调参；阈值改动只能赛前用带标签数据预注册。
