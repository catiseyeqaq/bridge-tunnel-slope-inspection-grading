# 城市路桥隧边坡结构病害智能巡检与分级评定

### 城市路桥病害智能巡检系统 · 多信号风险门控的大小模型按需协同架构

> **私有仓库** · 行业智能体创新挑战赛「赛题四」最终提交架构
> 答辩序号 4 ｜ 仅供内部查阅与归档，不对外分发

面向城市桥梁与轨道结构外观病害的智能巡检与分级评定系统。核心思路：**让轻量模型承担常规巡检，让大模型在关键时刻提供复核。**

## 〇、真实运行证据

| 指标 | 结果 |
|---|---|
| 全量识别 | **330 / 330 完成**（每张均有实时视觉计算） |
| 按需复核 | **4 / 4 完成**（桥梁 3 张 / 轨道 1 张） |
| 线上入口计时 | 约 **156 秒**（同次完整进程约 170 秒） |

> 两次真实运行均为 330 张，非严格同环境消融。

## 一、为什么不能直接把巡检图交给大模型

三个任务挑战决定了架构必须分层：

| 挑战 | 具体表现 | 对应设计 |
|---|---|---|
| **病害类别长尾** | 细类样本少，26/48 类病例标签仅 1 例 | 不靠全量微调，改用特征 + 分类头 |
| **全量大模型成本高** | 模型加载与推理占用时间、资源 | 2B 承担全量，27B 只做复核 |
| **需要可复查的记录** | 巡检要变成可入库台账 | 七字段合同 + 保留原图身份 |

## 二、算法架构

### 主链路

```
输入图片
   ↓
2B 提取视觉特征（全量识别）
   ↓
轨道 / 桥梁 任务识别
   ↓
多信号风险门控（三级风险筛选）
   ├── 无需复核 → 保留 2B 初判 → 统一规则校验后输出
   └── 触发复核 → 27B 独立看图提出建议 → 检查通过才允许更新
```

### 27B 不是最终裁判

| 结果 | 处理 |
|---|---|
| 门控未触发 | 保留 2B 初判，统一规则校验后输出 |
| 完成复核 | 27B 独立看图提建议，**检查通过才允许更新** |
| 复核异常（缺模型 / 超时 / 非法输出） | **保留有效 2B 初判** |

> 这条设计的含义：宁可承认能力降级，也不静默换模型糊过去。

## 三、行业任务适配

通用 2B 如何适配路桥病害任务？——**冻结 2B，只训练轻量分类头**。

| 项 | 数据 |
|---|---|
| 标注训练数据 | 轨道 **800 条** / 桥梁 **2602 条** |
| 分类头 | 逻辑回归（轨道 22 类 / 桥梁有无病害） |
| 桥梁病例库 | **698 条 / 48 种**已有标签 |

## 四、多信号风险门控

**哪些图片需要 27B？** 三级风险筛选机制，两类风险来源：

| 风险来源 | 触发条件 |
|---|---|
| **模型判断犹豫** | 多个类别分数接近，或接近有无病害边界 |
| **缺少训练支持** | 与已标注样本差异较大 |
| 补充规则 | 高置信且参考严重不足时也可触发复核 |

线上实测 330 张中的真实触发案例见 `code/evidence/`。

## 六、关键设计

### 6.1 七字段合同

桥梁记录需：名称、缺损类型、性状描述、评定标度等字段；轨道记录按既有作业习惯只落缺损类型。**智能体按业务合同填报，不混表**。

### 6.2 门控阈值（evidence/reports 中有实验记录）

风控门不是拍脑袋定的，`reports/gate_threshold_study.json` 记录了阈值扫描过程。门控的作用是**用有限算力覆盖最可能出错的样本**。

### 6.3 可复现性

- `REPRODUCIBILITY.md`：环境、配置、校验流程
- 所有 manifest 记录 SHA256，支持逐项核对
- 运行入口不改模型、不改门控、不改验收规则
