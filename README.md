## 一、最终架构

### 主链路

```
全量影像
   ↓
2B 视觉嵌入巡检（全图扫描）
   ↓
风险门控 risk_gate（严重度筛选）
   ↓
27B 训练模型复核（预算受限）
   ↓
七字段合同校验 → 落库
```

**入口**：`code/run.py`，默认加载 `code/code/configs/submission_risk_gate_teacher.yaml`

### 三层职责分离

| 层 | 职责 | 不做 |
|---|---|---|
| 感知层（2B） | 全图巡检、候选病害召回 | 不做最终定性 |
| 门控层（risk gate） | 按严重度筛出需复核样本 | 不改写感知结果 |
| 复核层（27B） | 对高风险样本二次判定 | 不越权处理低风险样本 |

### 降级策略（真事，写进代码里）

- 27B 缺失或 SHA 不匹配 → **preflight 保留合法的 2B 结果**
- 2B 也缺失 → **显式启动失败，不替换为其他模型**
- 实际能力边界：**2B 主链 + 可选 27B 回退**

> 这条设计的意思是：宁可承认能力降级，也不静默换模型糊过去。

## 三、关键设计

### 3.1 七字段合同

桥梁记录需：名称、缺损类型、性状描述、评定标度等字段；轨道记录按既有作业习惯只落缺损类型。**智能体按业务合同填报，不混表**。

### 3.2 门控阈值（evidence/reports 中有实验记录）

风控门不是拍脑袋定的，`reports/gate_threshold_study.json` 记录了阈值扫描过程。门控的作用是**用有限算力覆盖最可能出错的样本**。

### 3.3 可复现性

- `REPRODUCIBILITY.md`：环境、配置、校验流程
- 所有 manifest 记录 SHA256，支持逐项核对
- 运行入口不改模型、不改门控、不改验收规则

| 类别 | 说明 |

| 基础模型权重 | 2B 嵌入模型、27B 教师模型（由评测环境提供） |
